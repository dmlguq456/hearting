# lab

Lab is the work of designing and running research and experiments, and of reading what they measured.

## Fundamentals (not dropped)

- Keep confirming and exploring apart. — Tell the analyses planned in advance (confirming) from the ones done afterwards (exploring). Exploring is not forbidden; it is labeled as exploring. [1–3]
- Plan before looking at the data. — Settle the hypothesis and the analysis plan before seeing the data. [1–3]
- Make it reproducible. — Leave the methods, data, and code so that someone else can get the same result. [1–3]
- Start small. — Check the setup small and cheap before running it large. [4–6]
- Set a baseline and change one thing at a time. — Keep a baseline to compare against, and change only the one thing you want to learn about. [4–6]
- Count the variation. — Check whether a gain holds when the seed changes, rather than trusting one run. [4–6]
- Record every run. — An experiment that was not tracked is as good as one that did not happen: keep its name, settings, number of attempts, result, and how to reproduce it. [4–6]

## Not decided here

These differ from person to person and team to team, and this page leaves them open: the order of the work, whether a plan is registered publicly or reviewed before the results, how many seeds are run and how the variation is estimated, which tracking tools are used, how strong the means of reproduction must be, who permits a full run and when, and what makes a small piece of work small enough to skip a form.

## Boundaries with other fields

- Lab covers the question, the hypothesis, the design, the running, the interpretation, and the judgment of reproducibility. Writing the result up as a paper or a report is `docs`.
- Collecting what is already known from outside sources to answer a set question is `research`. A systematic review is a method that both fields use.
- Software that runs an experiment is `code`; deciding what the experiment must show is lab.
