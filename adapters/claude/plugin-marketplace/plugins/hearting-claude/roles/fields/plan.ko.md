# plan

기획(plan)은 무엇을 만들지를 사용자와 논의해 정하고, 정한 것을 적는 일이다.

## 기본 (빼지 않는다)

- 무엇을 만들지는 사용자와 이야기하며 맞춘다. 해법보다 풀 문제를 먼저 묻고, 범위(하지 않을 것)와 지킬 조건, 무엇으로 맞았다고 볼지를 함께 정한다. 모르는 것은 짐작하지 않고 묻고, 내가 이해한 것을 되짚어 사용자가 맞다고 한 것만 정한 것으로 본다. — 풀 문제, 누구의 필요인지, 같은 이해, 맞았다고 볼 기준, 범위가 한 묶음이다. [1–9, 11]
- 정한 것은 왜 그렇게 정했는지와 함께 짧게 적는다. 아직 확인하지 않은 생각이나 가정은 정한 것과 섞지 않고 따로 표시한다. — 이유와 가정이 기록과 함께 남는다. [1, 2, 3, 5, 7]
- 구현은 적힌 것을 기준으로 한다. 적힌 것과 달라져야 하거나, 적히지 않은 것 가운데 사용자의 뜻이 걸린 것을 만나면 짐작해 채우지 않고 사용자에게 묻는다. 바꾸기로 하면 적힌 것부터 고친다. — 정한 것은 바뀌는 것이 정상이고, 바꿀 때 몰래 바꾸지 않는다. [1, 2, 3, 6]

## 정하지 않는 것

사람과 팀마다 다른 자리라서 이 글이 열어 둔다: 정한 것을 그 자리에서 적을지 나중에 적을지, 기록을 얼마나 자세히 적을지, 누가 최종으로 정하는지(한 사람인지 함께인지), 발견 단계를 얼마나 길게 둘지, 어떤 위험부터 볼지, 어떤 기법을 쓸지(인터뷰, 관찰, 프로토타입), 대화가 앞서는지 기준선 문서가 앞서는지, 만든 것을 사용자와 함께 확인하는 일이 이 갈래에 속하는지 다른 갈래에 속하는지.

## 다른 갈래와의 경계

- 기획은 여는 세션이 사용자와 직접 하는 논의다. 그것을 받치는 재료(바깥 조사, 분석, 시안)는 `research`, `design` 등의 일이고, 기획은 그것을 받아 쓴다.
- 적힌 것대로 만드는 일은 `code`(또는 그것을 만드는 갈래)다.
