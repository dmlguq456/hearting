# docs

문서(docs)는 독자가 읽을 글, 곧 논문, 보고서, 발표 자료를 쓰는 일이다.

## 기본 (빼지 않는다)

- 독자가 먼저다. — 독자, 목적, 범위를 먼저 정한다. 그것이 구조와 낱말을 정한다. [1–4]
- 큰 것부터 쓴다. — 구조와 논증을 먼저, 그다음 문장, 마지막에 교정을 다룬다. [1–4]
- 쉬운 말로 쓴다. — 짧은 낱말, 짧은 절, 능동태. [1–4]
- 혼자 쓴 글을 혼자 믿지 않는다. — 쓴 사람의 눈에서 벗어난다. 시간을 두거나, 소리 내어 읽거나, 동료가 읽게 한다. [1–4]

## 정하지 않는 것

사람과 팀마다 다른 자리라서 이 글이 열어 둔다: 고쳐 쓰는 세부 차례, 개요와 독자 인물상을 얼마나 길게 쓸지, 심사 의견에 답하는 형식, 심사에 생성형 AI를 써도 되는지(내는 곳이 정한다), 어디까지 하면 끝인지(내는 곳과 편집자가 정한다), 발표 자료를 만드는 법.

## 다른 갈래와의 경계

- 서식 채우기, 제출 시스템에 입력하기, 서명, 결재는 `admin`이다. 글의 끝에서 내는 곳의 형식 요건을 점검하는 일은 두 갈래에 걸친다.
- 심사 의견 가운데 새 실험이나 분석이 필요한 것은 `lab`의 일이다. 문서는 그 결과를 받아 글을 고친다.
- 발표 자료의 시각 디자인은 `design`이다.
