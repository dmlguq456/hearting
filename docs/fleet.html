Fleet · part of Hearting

Every agent, on one screen.

Background agents leave you guessing. Is it still running? Is it stuck? Is it waiting for you? Did it finish? Fleet answers in one terminal view, for every Claude Code, Codex, and OpenCode session on your machine and every worker Hearting dispatched from them.

$fleet Install Hearting See the screens
The problem

A background agent is a black box until you open its terminal.

With several sessions across three runtimes, and workers dispatched under them, you end up opening windows one by one to learn the same three things.

ALIVE?

What is running

Working, idle, and waiting-for-you have different marks. Each session shows what it is doing now and for how long.

STUCK?

What went quiet

A stalled worker shows up as a stalled worker, not as a parent session that went quiet. Rows whose parent is gone are shown, not dropped.

WAITING?

What needs you

QUESTIONS lists every agent waiting for your answer or approval, since when, and for which request.

The screens

One screen per question.

Press Tab to move between views. Select a session or a request to open its page.

OVERVIEW

Every session, grouped by project.

Each project's line says where it stands, and each session shows what it is doing right now.

  • Per project: open requests, questions waiting for you, what is left to decide, and when it last changed.
  • Per session: runtime, model and effort, a short title, context left, what it is doing now, and for how long.
  • Marks: working, idle, and waiting-for-you each look different.
  • Top row: each runtime's usage-window gauges, and how many sessions are working, idle, or waiting.
ROUTES

Each request, stage by stage.

A stage line such as plan › execute › test › report, with the workers running under it.

  • See which stage a request is in and which worker, on which model, is running it.
QUESTIONS

Everything waiting for your answer.

Every agent waiting for an answer or an approval: which session asks, what kind of question, for which request, and since when.

  • Older waits stay listed until you answer or the work ends. Nothing drops off for its age.
  • Answer from Fleet when the runtime offers a reply path. Otherwise Fleet points you to the session.
SESSION PAGE

One session, in full.

State, context left, what it is doing now, its request, the sessions it steers, and the GPU it holds.

  • Select any session in the tree to open its page.
RESOURCES

What is using the machine.

CPU, memory, and per-GPU use on this machine and on any hosts you configured, with the session that owns each GPU process.

  • Even without configured hosts, Fleet shows this machine's CPU and GPU use.
REQUEST PAGE

A request's stage graph and raw output.

Select a request to see its stages, and under them the owner's raw output: tool calls and results in order, without opening the runtime itself.

  • Setup done, one stage running, the rest pending, and what the owner just did.

PEERS

Which sessions watch or steer which, and their last exchange.

HISTORY

Earlier sessions of each terminal seat, so work that continued in a new session stays traceable.

MEMORY

Per project: the newest decisions, open work by stage, and the latest records saved to shared memory.

MODELS · SYSTEM

Which real model each budget maps to, and the installed Hearting release.

Why you can trust it

It shows what the work recorded, and nothing it made up.

01

Built from the work’s own records

Fleet reads the attempt registry the dispatcher writes and each runtime’s own session state. It does not guess from what a terminal printed.

02

Unknown stays unknown

A value Fleet could not read is shown as ?. Never as zero, never as success.

03

Watching changes nothing

Observation never completes, retries, or cleans up work. Fleet acts only on what you select, such as answering a waiting question.

Run it

Installed with Hearting. One word to start.

Open a second terminal next to your agent and run fleet.

fleet              # the Explorer, full screen (needs curses)
fleet --once       # one plain snapshot
fleet --json       # the same state as JSON, for scripts
fleet-monitor      # the earlier group/process view

Titles and Fleet’s own words follow your language. Set title_language in ${XDG_CONFIG_HOME:-~/.config}/hearting/fleet.json to override it.

--once and --json need no curses, so they also work on Windows under Git Bash (experimental).

Known limits

Fleet is not light yet.

≈ 1/3of one CPU core

≈ 0.8GB of memory

One Explorer window, on that machine.

≈ 6seconds to first screen

The first full screen takes about this long to draw when the history is long.
